# Stream Deck 7.5.1 Package Integration Design

## Goal
Use the user-owned `Stream_Deck_7.5.1.22901.pkg` as AetherBrowser's authoritative Stream Deck 7.5.1 compatibility/reference source while keeping execution native to Linux/Rust and embedded inside AetherBrowser.

## Source Package Contract
- Expected host path: `/home/benji/Downloads/Stream_Deck_7.5.1.22901.pkg`.
- Accepted basename aliases may include a browser-added numeric suffix, but host auto-discovery prefers the exact canonical basename first.
- Reference SHA-256 from the inspected upload: `8cc1f0b875839e2d50618a37cad2f46b689cad1d3fe1df1af1e373303515ffe8`.
- Package format is a macOS XAR installer containing `Stream Deck.app`; AetherBrowser must never execute the Mach-O application or dylibs.
- Vendor binaries/assets are not redistributed in AetherBrowser release artifacts.

## Imported Compatibility Data
The importer extracts/normalizes user-owned structured resources needed for compatibility and materializes a safe, non-executable browser-asset cache from the same local package:
- `DefaultProfiles/StreamDeckPlus_macDefault.streamDeckProfile`.
- `.sdPlugin/manifest.json` built-in plugin definitions and supported controller declarations.
- Property-inspector/PluginUI path metadata when declared by manifests.
- Stream Deck+ Keypad/Encoder profile layout data.
- PageIcons, TouchBackgrounds and InfobarLayouts indexes and metadata.
- Safe browser-renderable asset members (`.png`, `.jpg`, `.jpeg`, `.svg`, `.json`) from those three resource families are copied into the user-local Elgato cache so the embedded Stream Deck Studio can consume the real package visuals/layout manifests rather than approximate them. Executables, dylibs, scripts, fonts, and plugin runtime code are never materialized into the browser asset cache.

The inspected Stream Deck+ default profile identifies device model `20GBD9901`, schema `2.0`, and is the baseline for Stream Deck+ compatibility. AetherBrowser normalizes this into the existing `ProfileStore` rather than running vendor code.

## Runtime Architecture
1. `aether-deck` gains an Elgato package importer module.
2. Import operates on the local `.pkg`, using safe bounded archive parsing/extraction via system tools available on AetherForge (`bsdtar`/`xar` when present, with a portable Python XAR reader fallback generated by the installer only if needed). It rejects traversal paths and never extracts executables into an executable runtime location.
3. Imported normalized metadata is stored under `~/.local/share/aetherforge/aether-browser/streamdeck/elgato-7.5.1/` as AetherForge-owned JSON/index data. Safe browser-renderable assets are stored under its `browser-assets/` child and referenced by normalized records. Original package remains untouched.
4. Stream Deck Studio loads this normalized catalog before falling back to the built-in AetherForge catalog. Existing AetherForge-native actions remain available and are not replaced by unsupported vendor executables.
5. Imported profile data can seed/create an editable native AetherForge profile. Vendor source remains read-only.
6. The existing AetherBrowser external-app containment model remains authoritative: Stream Deck Studio lives inside the main browser by default and restart re-integration is preserved.

## Compatibility Rules
- `Keypad` maps to `ControllerKind::Keypad`; `Encoder` maps to `ControllerKind::Encoder`.
- Stream Deck+ geometry remains 4x2 keys + 4 encoders.
- Unknown plugin controllers/actions remain visible as compatibility metadata but are not executable unless a native AetherForge action adapter exists.
- Property inspector HTML/JS from the vendor package is not executed by default. It may be indexed for schema/reference and surfaced only through a constrained, non-privileged viewer if explicitly supported later.
- No DRM/licensing bypass, no private Marketplace API emulation, no copying or executing proprietary macOS plugin binaries.

## UI
Stream Deck Studio gets an `Elgato 7.5.1` package status section in the existing Marketplace/integration area showing:
- package discovered / missing;
- package version/build and SHA-256 status;
- number of normalized built-in plugins/actions;
- Stream Deck+ baseline profile status;
- `Import / Refresh` action;
- `Create Editable Copy` action for the normalized Plus profile.

The action palette uses imported names/controller compatibility when available while retaining native AetherForge execution adapters. The embedded Studio also consumes the imported browser-asset cache: TouchBackground PNG/JPEG assets can drive the Stream Deck+ touch-strip preview, and PageIcon/Infobar manifests/assets are surfaced by the in-browser Elgato asset browser so layout choices come from the real package instead of hard-coded approximations.

## Failure Behavior
- Missing package: Studio remains usable with native catalog and reports the canonical expected path.
- SHA mismatch: import is allowed only as an explicitly different package version; 7.5.1 identity is not claimed.
- Malformed archive/manifest/profile: fail closed for that item, preserve previous normalized import, and report the specific parse error.
- Import failure must not prevent AetherBrowser or Stream Deck daemon startup.

## Release / Verification
Canonical release becomes `2.1.48`.
Required gates:
- package discovery/path contract;
- exact uploaded 7.5.1 metadata contract (model `20GBD9901`, profile version `2.0`, Keypad + Encoder);
- manifest normalization tests;
- no Mach-O execution/no vendor payload redistribution contract;
- browser-asset cache allowlist contract (PNG/JPEG/SVG/JSON only; no executable/dylib/script/font extraction);
- embedded Studio consumes imported package assets/layout metadata rather than merely indexing them;
- path traversal rejection;
- editable-copy profile import contract;
- embedded Stream Deck Studio containment regression;
- existing capture safety, Twitch login, OBS/Streamlabs, omnibox, host-Clippy regressions.
