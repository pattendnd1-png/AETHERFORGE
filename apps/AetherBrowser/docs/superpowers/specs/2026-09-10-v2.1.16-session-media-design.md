# Aether Browser v2.1.16 Session + Media Reliability Design

## Goal
Ship v2.1.16 with durable normal-profile website logins, ephemeral Private mode, and reliable Twitch / YouTube / YouTube Music playback that cannot remain in an endless buffering state.

## Constraints
- Canonical release version is `2.1.16`; do not reuse `2.1.15`.
- Preserve all v2.1.15 performance and right-rail viewport reclamation work.
- Preserve Servo 0.5.0 as the web engine and native egui/glow chrome.
- Do not add Chromium, WebKit, CEF, Electron, or yt-dlp.
- Normal browsing persists site session state until explicit sign-out or site-data clearing.
- Private mode is ephemeral and must not reuse or write normal-profile site state.
- Playback state must be explicit and bounded: `resolving -> buffering -> playing | ended | error`.
- A provider may never remain `buffering` forever; startup watchdog failure must surface as `error` with diagnostics.

## Persistent web sessions
`aether-profile` becomes the owner of profile storage paths and privacy semantics. The normal profile receives an on-disk Servo profile directory under `$XDG_DATA_HOME/aetherforge/aether-browser/profiles/default` (falling back to `~/.local/share/...`). Private sessions receive a unique temporary directory deleted on shutdown.

The Servo runtime must construct all webviews from the same active profile configuration for the lifetime of a browser window. Tabs share cookies, local storage, IndexedDB and other Servo-supported origin data through that profile. No login token is copied into Aether Library history or diagnostics.

A native `Clear Site Data` operation deletes profile-origin state only after webviews are closed or the browser is restarted into a clean profile. Sign-out performed by the website remains authoritative.

## Twitch playback
Twitch live and VOD use a single helper lifecycle abstraction instead of the current fixed 900 ms sleep. The helper is spawned with captured stdout/stderr and a readiness probe. The media service waits for localhost readiness with a bounded deadline and watches helper/process exit.

Live playback consumes the resolved stream through GStreamer only after the helper is ready. VOD resource identifiers (`videos/<id>`) are no longer rejected; they use the helper's supported resource form and the same readiness path.

The media runtime owns a watchdog. If no decoded frame is observed within the configured startup deadline, state becomes `error` and all helper/GStreamer children are terminated. If playback later stalls beyond the runtime stall deadline while the process remains alive, state also becomes `error` with a provider-specific reason.

## YouTube + YouTube Music playback
YouTube URLs continue to be classified by the Rust provider layer. Resolution remains Rust-native. The current `rusty_ytdl` chunk-to-`fdsrc ! decodebin` path is replaced by an explicit resolved-media descriptor that records container/protocol and chooses a matching GStreamer source pipeline instead of assuming arbitrary chunks form a single self-describing stream.

YouTube watch/live/shorts all resolve through the native media service. YouTube Music remains a Servo website for browsing/search/library UI, but playable watch/media URLs are handed to the same native YouTube playback backend. Website login persistence comes from the normal profile, so Google/YouTube/YouTube Music sessions survive browser restarts.

## Playback state machine
Every playback generation has timestamps for resolve start, buffering start, first frame and last frame. State transitions are monotonic for that generation. New playback cancels the previous generation and kills its children.

Diagnostics include provider, resource, state, elapsed milliseconds, helper readiness, first-frame status and sanitized errors. Secrets, cookies and authorization headers are never printed.

## Verification
- Unit tests prove normal/private profile path semantics.
- Runtime contract tests prove multiple webviews share the selected normal profile and Private uses an isolated temporary profile.
- Twitch tests prove live and VOD are accepted, readiness is polled rather than slept, and timeout becomes `error`.
- YouTube tests prove source selection is descriptor-driven and Music playback dispatches to the YouTube backend.
- Watchdog tests prove `buffering` cannot outlive the deadline without transitioning to `playing`, `ended`, or `error`.
- Existing v2.1.15 right-rail, performance, viewport, OpenAI, install-promotion, and provider-rendering contracts remain green.
- Fix the existing v2.1.15 Clippy blocker in `aether-telemetry` by deriving `Default` for `LinuxTelemetrySampler`.
