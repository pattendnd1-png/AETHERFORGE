# v2.1.16 Media Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Twitch live/VOD and YouTube/YouTube Music playback transition reliably to playing or a visible error instead of buffering forever.

**Architecture:** `aether-media-service` owns a bounded playback state machine and provider workers. Twitch uses helper readiness/process monitoring instead of a fixed sleep; YouTube resolves to an explicit media descriptor and chooses a matching GStreamer source path; YouTube Music dispatches playable media to the same YouTube backend.

**Tech Stack:** Rust 2024, GStreamer CLI/runtime already used by Aether Browser, twitch-hls-client, rusty_ytdl 0.7.4 initially unless a host-proven Rust-native resolver replacement is required.

**Spec:** `docs/superpowers/specs/2026-09-10-v2.1.16-session-media-design.md`

## Global Constraints
- Canonical release version is `2.1.16`.
- No Chromium/WebKit/CEF/Electron/yt-dlp.
- No endless `buffering`; startup/stall deadlines must end in `playing`, `ended`, or `error`.
- Provider errors must be sanitized and visible.
- Preserve normal web browsing in Servo.
