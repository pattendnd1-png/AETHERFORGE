# AetherForge BEACN Control v0.1.13 Windows-Parity Safe DSP Design

## Goal
Deliver the next canonical BEACN Control release with the structure, interaction model, density, Live Profiles, microphone processing, headphone workflow, meters, recorder, and output workflow of the Windows BEACN 1.4 generation while retaining AetherForge DragonGlass styling and the v0.1.11 system-audio protection invariant.

## Safety invariant
Linux ALSA/PipeWire remains the permanent owner of BEACN USB audio. The application must never call the direct BEACN USB connect/claim path in normal runtime, and must never silently fall back to vendor-interface writes. If software-DSP dispatch is unavailable, controls remain editable/persistent as profile state but the UI reports that live DSP dispatch is unavailable rather than claiming audio was changed.

## Architecture
The app gains a pure Rust `software_dsp` state model that represents the Windows-style microphone and headphone workstation independently from the staged `HardwareController`. Existing real PipeWire source/sink controls, volume/mute, recorder, routing discovery, duplex-profile repair, and health probes remain live. A small backend-status contract describes whether a verified AetherStream mutating DSP adapter is available; v0.1.13 never guesses postcard enum layout.

## Windows BEACN 1.4 workflow target
The Mic workspace keeps a collapsible device/module rail, an anchored Equalizer & Enhancement area, a secondary processing tab row, a voice recorder strip, and a distinct end-of-chain Mic Output surface. Secondary processing covers Compressor, Expander, Noise Suppression, De-Esser, Exciter, and Headphones. Controls are scroll-safe at compact, standard, and wide widths.

## Live Profiles
A Live Profile contains PipeWire source/sink identity and level/mute plus the complete software-DSP state. Every edit marks the active profile dirty and autosaves after a bounded debounce. Explicit snapshots are immutable point-in-time profile files that can be restored. Loading a Live Profile restores UI/DSP state and applies only already-proven PipeWire level/mute operations; it does not change system defaults.

## Microphone DSP model
The profile model includes microphone EQ, compressor, expander, suppression, de-esser, exciter/enhancement, monitor level, output gain, mono/balance-related state where relevant, and bypass/enabled flags. Parameters are clamped to documented/safe ranges. Microphone EQ retains the proven nine-band clean-room model used by the existing project.

## Headphone workflow
The software workflow exposes ten parametric EQ bands per ear, left/right selection, link/unlink, mono mode, balance, headphone level, microphone monitor level, preset naming, and a binaural-personalization state/foundation. Linking ears mirrors edits to the opposite ear; enabling link synchronizes the inactive ear from the selected source ear. This software model does not alter the staged nine-band hardware-protocol structs.

## Backend truthfulness
`DspBackendState` distinguishes `Unavailable`, `Ready`, and `Error`. A verified adapter may later implement the dispatch trait, but v0.1.13 does not fabricate binary IPC. UI badges say PROFILE ACTIVE / DSP BACKEND UNAVAILABLE when only state/persistence is active. Direct USB remains blocked regardless of backend state.

## Visual language
Retain AetherForge DragonGlass: dark smoked/translucent cards, minimal borders, rounded surfaces, indigo/violet/dark-blue accents, pale lavender/near-white text, compact controls, and no proprietary BEACN artwork. Match Windows BEACN proportions and information hierarchy rather than its proprietary brand skin.

## Verification
Release qualification requires version-specific source contracts for Windows parity, Live Profiles, ten-band headphone workflow, truthful DSP backend state, and v0.1.11 pass-through protection, plus the inherited runtime-audio/output-profile/graphical-session/egui API contracts. Target host gates remain fmt, strict Clippy `-D warnings`, all tests, release build, graphical-session recovery, safe output-profile repair, read-only probe, and install.
