# BEACN v0.1.12 Windows-Parity Safe DSP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship canonical v0.1.12 with Windows BEACN 1.4-style workflow/functionality while preserving permanent ALSA/PipeWire ownership and truthful backend behavior.

**Architecture:** Add a pure Rust software-DSP/profile model beside the permanently blocked direct-USB controller. The UI edits that model and persists it through Live Profiles/snapshots; existing proven PipeWire operations remain live. A backend capability object gates future AetherStream DSP dispatch without guessing wire types.

**Tech Stack:** Rust 2024, egui/eframe 0.36.2, existing PipeWire CLI adapters, std-only profile persistence, pinned staged beacn-lib v0.4.3.

**Spec:** `docs/superpowers/specs/2026-09-13-beacn-v0.1.12-windows-parity-safe-dsp-design.md`

## Global Constraints
- Canonical version is exactly `0.1.12`; no RC/rN suffixes and no version reuse.
- Direct BEACN USB control remains blocked to preserve ALSA/PipeWire microphone availability.
- AetherStream remains authoritative for system-wide PipeWire/software DSP; BEACN Control must not create a competing graph.
- Never report live DSP success unless a verified backend says the command was accepted.
- Existing PipeWire volume/mute/recorder/routing/profile repair behavior remains live and unchanged.
- All pages remain scroll-safe and DragonGlass themed.
- Host qualification requires fmt, strict Clippy `-D warnings`, tests, release build, graphical-session recovery, safe output-profile repair, read-only probe, and install.
