# AetherForge BEACN Control v0.1.15 Private DSP Windows Reforge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver v0.1.15 with a Windows-BEACN-inspired DragonGlass workstation and a live, app-private Rust microphone DSP source that never depends on AetherStream/system DSP or direct USB ownership.

**Architecture:** Preserve the physical BEACN ALSA/PipeWire source, capture it explicitly with `pw-record`, process float32 mono blocks in a pure Rust engine, and publish a separate namespaced source through PipeWire Pulse `module-pipe-source`. Keep the v0.1.13 UI/profile model while replacing the staged AetherStream backend concept with a private runtime controller.

**Tech Stack:** Rust 2024, std-only DSP/runtime orchestration, egui/eframe 0.36.2, PipeWire command-line clients (`pw-record`, `pactl`), Pulse-compatible `module-pipe-source`.

**Spec:** `docs/superpowers/specs/2026-09-18-beacn-v0.1.15-private-dsp-windows-reforge-design.md`

## Global Constraints

- Canonical version is exactly `0.1.15`.
- No version reuse or RC/rN suffix.
- No AetherStream/system-DSP dependency or action.
- No direct BEACN USB claim or `beacn-lib` runtime dependency.
- No default-device mutation.
- Raw BEACN source remains usable regardless of private DSP state.
- Only app-owned namespaced virtual nodes/modules may be created or removed.
- Windows installers are static clean-room references only and are not redistributed.
