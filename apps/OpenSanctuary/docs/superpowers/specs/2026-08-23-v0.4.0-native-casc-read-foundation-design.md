# OpenSanctuary v0.4.0 Native CASC Read Foundation Design

## Goal

Add a clean-room, read-only native CASC transport foundation that can resolve a local encoding key through Diablo III's local index, read the corresponding archive envelope, and BLTE-decode the stored bytes without modifying Blizzard content.

## Scope

v0.4.0 implements the transport layer only:

- `.build.info` parsing remains supported and gains build-config resolution.
- Build config files are resolved from the local `Data/config` tree.
- 16-byte CASC keys and 9-byte local-index prefixes have typed Rust representations.
- Local `Data/data/*.idx` files are selected deterministically per bucket and parsed into EKey-prefix to archive-location mappings.
- `data.NNN` archive records are read with strict offset/size bounds and the 30-byte CASC envelope removed.
- BLTE supports `N` raw, `Z` zlib, and recursive `F` chunks.
- BLTE `E` encrypted chunks are rejected explicitly until OpenSanctuary has a legitimate key source.
- Chunk digests are verified when a BLTE chunk table provides them.
- Decompression has output-size and recursion limits.
- `CascStorage` provides a read-only facade for EKey reads and build-config-addressed blobs.

v0.4.0 does not parse the encoding table, Diablo III root manifest, logical asset names, or gameplay data. Those remain later milestones.

## Architecture

`sanctuary-casc` is split by responsibility:

- `build.rs`: `.build.info`, build config location, and line-oriented build config parsing.
- `key.rs`: full 16-byte CASC keys plus 9-byte local-index prefixes and hex conversion.
- `index.rs`: deterministic index-file selection and guarded local-index parsing.
- `archive.rs`: bounded `data.NNN` reads and archive-envelope validation.
- `blte.rs`: bounded BLTE decoding.
- `storage.rs`: read-only facade joining build config, local index, archive reader, and BLTE decoder.
- `lib.rs`: existing inventory/cache compatibility API plus module re-exports.

The existing inventory/probe API remains backward compatible so launcher and engine behavior from v0.3.12 does not regress.

## Data Flow

`.build.info` → build key → `Data/config/<aa>/<bb>/<build-key>` → build configuration → EKey → selected local `.idx` bucket → archive index/offset/encoded size → `data.NNN` → 30-byte envelope → BLTE → decoded bytes.

## Error Handling

Malformed/truncated structures return `SanctuaryError::ContentStoreUnreadable` with contextual messages. Unsupported encrypted BLTE chunks return `SanctuaryError::UnsupportedBuild` so the limitation is explicit. All file reads are read-only. Archive offsets, encoded sizes, BLTE header sizes, chunk counts, compressed sizes, decompressed sizes, recursion depth, and total output are validated before allocation or append.

## Testing

Synthetic fixtures cover key parsing, build-config lookup, deterministic index selection, duplicate index entries, archive bounds, envelope-key validation, headerless raw BLTE, chunk-table raw BLTE, zlib BLTE, recursive BLTE, digest mismatch, encrypted-chunk rejection, decompression limits, and an end-to-end local EKey read through `CascStorage`.

## Release Policy

This is canonical OpenSanctuary `0.4.0`. No revision or release-candidate suffixes are permitted. One ZIP and one TAR.GZ are canonical source artifacts, plus a cumulative `0.3.12 → 0.4.0` patch.
