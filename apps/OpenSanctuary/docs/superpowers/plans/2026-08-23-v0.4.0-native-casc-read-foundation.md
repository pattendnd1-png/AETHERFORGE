# OpenSanctuary v0.4.0 Native CASC Read Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only pure-Rust CASC transport that resolves local EKeys to bounded archive reads and BLTE-decoded bytes.

**Architecture:** Keep the existing inventory/cache API stable while splitting CASC transport responsibilities into focused modules. `CascStorage` composes build config, local index, archive, and BLTE decoding; no encoding/root/gameplay parsing is added in this release.

**Tech Stack:** Rust 2024, std I/O, `flate2` for zlib, `md-5` for BLTE chunk digests, existing `sanctuary-core` errors.

**Spec:** `docs/superpowers/specs/2026-08-23-v0.4.0-native-casc-read-foundation-design.md`

## Global Constraints

- Full semantic version update only: `0.3.12` → `0.4.0`; no revision/RC suffix.
- Read-only access to user-owned Diablo III files.
- No Blizzard binary/data redistribution, credential capture, CDN scraping, or authentication bypass.
- Encrypted BLTE is rejected until a legitimate key source exists.
- Existing inventory/probe APIs remain source-compatible.
- Strict `cargo clippy --workspace --all-targets -- -D warnings` remains a release gate on Arch.
