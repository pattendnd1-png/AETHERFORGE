# ForgeHX 10.0.18 Full Output DSP Control Integration Design

## Goal
Extend ForgeHX with a DragonGlass full-range output DSP control surface backed by AetherStream 10.2.33 while preserving ForgeHX 10.0.17's direct HyperX microphone DSP path.

## Ownership
- ForgeHX remains the HyperX hardware and microphone-DSP control application.
- AetherStream remains sole system output/audio graph owner and sole app-facing system microphone publisher.
- ForgeHX sends typed output-DSP profiles to AetherStream; it never creates a competing output sink or rewrites PipeWire defaults.

## Immutable routing invariant
The selected audio endpoint `HyperX SoloCast 2 Analog Stereo` is user-owned and must never be changed by ForgeHX output-DSP operations, profile loads, live edits, daemon restarts, upgrades, or AetherStream synchronization. Output DSP targets `@DEFAULT_AUDIO_SINK@` without issuing source/sink/default-device routing commands.

## Microphone invariant
Keep the exact 10.0.17 path: physical HyperX capture -> ForgeHX direct Rust mic DSP -> AFXHXM01 -> AetherStream system microphone -> applications. No ForgeHX app-facing virtual mic source is reintroduced.

## Output DSP model
Mirror the AetherStream 10.2.33 schema: 19 output device classes; HPF/LPF/BPF/peak/notch/low-shelf/high-shelf filters; bass and clarity enhancements; gaming impact/mud/detail controls; preamp; output gain; limiter; bypass.

## Live edits
Every valid output-DSP edit is debounced and immediately applied through ForgeHX daemon IPC to AetherStream's `$XDG_RUNTIME_DIR/aetherstream/output-dsp.sock`. There is no Apply button for ordinary edits.

## Persistence
ForgeHX stores the editor profile in its namespaced state as JSON. AetherStream persists the authoritative active output profile in its own output-DSP database. ForgeHX never writes AetherStream's database directly.

## UI
Add a first-class `Output DSP` navigation page using the existing DragonGlass theme. Page sections: device profile, preamp/headroom, filters/EQ, bass, clarity, gaming, limiter/output, runtime status. Unsupported or invalid values are rejected before IPC.

## Protocol
ForgeHX IPC protocol increments to 12 for `OutputDspGet`, `OutputDspLiveUpdate`, and `OutputDspResetFactory`. The ForgeHX daemon owns AetherStream IPC and persistence; GUI never opens the AetherStream socket directly.

## Failure behavior
If AetherStream is offline or rejects a profile, ForgeHX reports the error and preserves the last editor profile. It does not alter audio routing. Existing microphone processing remains active independently.

## Verification
Static/TDD gates must prove schema parity, 19 factory classes, AetherStream socket framing contract, live-edit routing through daemon, DragonGlass page integration, version 10.0.18, and explicit absence of `wpctl set-default`, `pactl set-default-*`, or equivalent output-DSP routing mutation. Host verification runs cargo fmt/clippy/test/build and checks AetherStream runtime availability.
