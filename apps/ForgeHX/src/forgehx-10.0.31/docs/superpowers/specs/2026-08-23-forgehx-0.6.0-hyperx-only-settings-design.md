# ForgeHX 0.6.0 HyperX-Only Inventory and Settings Design

## Goal

Make the ForgeHX desktop application present only HyperX hardware while retaining non-HyperX discovery internally where it is required to correlate Linux audio/OpenRGB/libratbag nodes. Expand the device UI so every HyperX device class receives a class-specific settings/status surface built only from verified capability owners.

## User-visible inventory invariant

The GUI must never request or render the daemon's universal device list. The navigation rail, Home page, Devices page, selection lookup, Settings counts, empty states, and refresh validation operate exclusively on `ListHyperxDevices` / `hyperx_devices`.

The daemon may retain `all_devices` internally for discovery correlation, compatibility tests, and backend matching. `ListAllDevices` remains in IPC for backward compatibility and diagnostics, but it is not used by the ForgeHX GUI. No non-HyperX `DeviceInfo` may become selectable in the GUI.

## HyperX settings surfaces

Existing verified controls remain authoritative:

- Keyboard: model/topology, lighting through the selected Lighting owner, profile/polling metadata, wireless/battery/Hall/Rapid Trigger metadata.
- Mouse: native/libratbag DPI, polling, profiles, assignments and lighting only when the selected owner is writable.
- Headset / USB audio / audio interface: PipeWire volume and mute, EQ where owned, battery/status when available.
- Microphone: input volume/mute, ForgeHX input-only DSP, lighting where owned, firmware inventory/update qualification.
- Mousepad: lighting where owned plus device/backend status.
- Controller, webcam and monitor: battery/status, detected writable capability owners and a clear read-only state until a verified backend exists.

A new class-specific `Hardware` tab is added for Headset, Controller, Webcam, Mousepad, Monitor, AudioInterface and UsbAudio. It must not manufacture unsupported actions. For audio-capable classes it reuses verified PipeWire controls; for other classes it reports actual writable/read-only capability ownership.

## Safety

Capability priority remains ForgeHX Native > ForgeHX DSP > Linux Standard > OpenRGB/libratbag > Diagnostic. Name-only recognition never grants proprietary writes. Generic/raw firmware flashing remains absent. Microphone DSP remains input-only. Universal discovery never becomes a public write path for non-HyperX hardware.

## Release policy

The canonical release is ForgeHX 0.6.0 with Arch package identity `forgehx-0.6.0-1-x86_64.pkg.tar.zst`. No revision, RC, or r-number suffix is allowed. Exactly one canonical source archive and one canonical Arch build kit are produced.
