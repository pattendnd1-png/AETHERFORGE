# ForgeHX v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native Rust/Arch Linux HyperX control-suite foundation with safe HID discovery, persistent profiles, daemon IPC, CLI/GUI clients, PipeWire-facing audio discovery, and installable Arch packaging.

**Architecture:** A Cargo workspace separates pure domain types (`forgehx-core`) from hardware discovery (`forgehx-device`), audio integration (`forgehx-audio`), daemon state/IPC (`forgehx-daemon`), CLI (`forgehx-cli`), and GUI (`forgehx-gui`). The daemon is the sole state-changing hardware owner; unknown devices are diagnostic-only and vendor-specific writes are denied unless a registered protocol explicitly exposes the requested capability.

**Tech Stack:** Rust 2021, Cargo workspace, serde/serde_json, thiserror, hidapi, tokio, interprocess-style Unix sockets via tokio `UnixListener`/`UnixStream`, eframe/egui, dirs, clap, tracing, PipeWire command discovery (`wpctl`/`pw-cli` best-effort in v0.1), systemd user services, udev, Arch `makepkg`.

## Global Constraints

- Target Arch Linux and Arch-derived x86-64 Linux.
- Native Rust application; no Wine/NGENUITY wrapper.
- Enumeration and diagnostics are safe-by-default.
- No guessed vendor-specific writes to unknown devices.
- Firmware/bootloader flashing is not exposed in v0.1.
- Unsupported capabilities return explicit errors, not successful no-ops.
- GUI and CLI share the daemon IPC protocol.
- Profiles live beneath the XDG config directory and preserve the last valid configuration on parse/validation failure.
- A failed device operation must not crash the daemon.

## File Map

- `Cargo.toml` — workspace membership and shared package metadata.
- `crates/forgehx-core/src/lib.rs` — IDs, capabilities, profiles, commands/replies, validation, shared errors.
- `crates/forgehx-device/src/lib.rs` — HID enumeration, HyperX registry, diagnostic model, write gate.
- `crates/forgehx-audio/src/lib.rs` — PipeWire node discovery and volume/mute command adapter.
- `crates/forgehx-daemon/src/lib.rs` — daemon state, request handling, profile store, fake-backend integration points.
- `crates/forgehx-daemon/src/main.rs` — Unix-socket server and hotplug refresh loop.
- `crates/forgehx-cli/src/main.rs` — clap commands and human/JSON output.
- `crates/forgehx-gui/src/main.rs` — egui device rail, capability tabs, status/footer, doctor view.
- `packaging/udev/70-forgehx.rules` — HyperX USB permissions.
- `packaging/systemd/forgehx-daemon.service` — user daemon.
- `packaging/desktop/io.forgehx.ForgeHX.desktop` — desktop launcher.
- `PKGBUILD` — Arch source package definition.
- `scripts/build-release.sh` — release build and source archive.
- `scripts/build-arch-package.sh` — `makepkg` wrapper.
- `scripts/install-local.sh` / `scripts/uninstall-local.sh` — explicit local install lifecycle.
- `README.md` — supported behavior, safety policy, build/run/install commands.
