# ForgeHX 0.5.0 Keyboard Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first ForgeHX 0.5.0 peripheral-platform slice: a first-class HyperX keyboard subsystem with current/legacy model recognition, exact legacy USB identities, capability metadata, OpenRGB fallback ownership, IPC/CLI/GUI visibility, and strict protection against name-only proprietary writes.

**Architecture:** Add a focused `forgehx-keyboard` crate containing data-only model descriptors and specificity-aware matching. The daemon uses keyboard metadata for UI/capability reporting while existing deterministic OpenRGB matching remains the lighting write backend unless a future exact native keyboard driver is explicitly registered. No proprietary keyboard write packet is added in this slice.

**Tech Stack:** Rust 2021, serde, existing ForgeHX core/device/daemon/ipc/cli/gui crates, OpenRGB fallback, Arch packaging shell guards.

**Spec:** `docs/superpowers/specs/2026-08-23-forgehx-0.5.0-hyperx-peripheral-platform-design.md`

## Global Constraints

- Release identity is exactly ForgeHX `0.5.0`, Arch `pkgrel=1`.
- Canonical artifacts are `ForgeHX-0.5.0-source.tar.gz` and `ForgeHX-0.5.0-Arch-BuildKit.tar.gz`; no RC/revision/r-number suffixes.
- `hidapi = { version = "2", default-features = false, features = ["linux-native"] }` remains unchanged.
- Name-only matches may supply keyboard metadata but never native/proprietary write authority.
- Exact HP vendor `0x03f0` permissions must be product-specific; never grant blanket HP hidraw write access.
- OpenRGB may own lighting only after deterministic external-device matching.
- Existing microphone DSP remains input-only.
- Existing mouse native/fallback support must remain intact.
- Cargo/rustc/makepkg are unavailable in this sandbox; Arch hardware is the compile/runtime gate.
