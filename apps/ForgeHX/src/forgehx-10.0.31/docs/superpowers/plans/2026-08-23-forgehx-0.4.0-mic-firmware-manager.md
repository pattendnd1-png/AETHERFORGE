# ForgeHX 0.4.0 HyperX Microphone Firmware Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safe, model-gated HyperX microphone firmware manager to ForgeHX 0.4.0 with firmware inventory, immutable staging, package validation, transaction journaling, CLI/GUI surfaces, and no generic raw flasher.

**Architecture:** A new `forgehx-firmware` crate owns firmware package/staging/transaction logic and a sealed model-adapter registry. The daemon remains the sole firmware authority, projects firmware state over versioned IPC, detaches ForgeHX microphone DSP before any future update-capable transaction, and exposes update only when a model adapter explicitly advertises a verified writer. The 0.4.0 baseline ships all known HyperX mic families with inventory/staging/validation support; write-capable adapters remain disabled until exact protocol/recovery evidence exists.

**Tech Stack:** Rust workspace, serde/serde_json, sha2, std filesystem APIs, existing ForgeHX Unix-socket IPC, PipeWire/WirePlumber integration, egui, clap, Arch PKGBUILD/package guards.

**Spec:** `docs/superpowers/specs/2026-08-23-forgehx-hyperx-mic-firmware-manager-design.md`

## Global Constraints

- Canonical release identity is `ForgeHX 0.4.0`; Arch package is `0.4.0-1`.
- Artifact names have no RC, revision, r-number, corrected, or duplicate suffixes.
- Firmware binaries are never bundled in ForgeHX artifacts.
- No generic raw firmware IPC or arbitrary report/endpoint write surface.
- Firmware writes are model-specific and disabled unless the adapter is verified `UpdateCapable`.
- Unknown/broad HP `03f0` devices never inherit firmware write authority.
- Existing input-only microphone DSP invariants remain intact.
- Existing HyperX mouse support remains intact.
- The sandbox has no Cargo/rustc/makepkg; executable static guards are required here and the user's Arch host remains the compile/hardware gate.
