# ForgeHX v0.3 Control Backends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn ForgeHX v0.2 device inventory into a capability-routed control plane using native verified drivers, Linux-standard audio/EQ, OpenRGB lighting, and ratbagd/libratbag gaming-mouse controls.

**Architecture:** `forgehx-core` owns backend-neutral capability/profile/IPC types. New `forgehx-backends` implements deterministic owner selection, OpenRGB TCP SDK, and a fixed-command ratbagd adapter; `forgehx-audio` owns ForgeHX namespaced PipeWire EQ files. `forgehx-daemon` is the sole routing and authorization boundary, while CLI/GUI only send typed IPC commands.

**Tech Stack:** Rust 2021, serde/serde_json, tokio, std::process, OpenRGB SDK TCP protocol v1..=5 on localhost:6742, ratbagd via packaged `ratbagctl`/D-Bus service, PipeWire/WirePlumber, egui/eframe 0.33.3, Arch PKGBUILD/systemd user units.

## Global Constraints

- Target Arch Linux / Arch-derived x86-64 Linux, Wayland/X11, PipeWire/WirePlumber.
- Workspace version is `0.3.0`; IPC protocol is `3`; profile schema is `2` with v1 migration.
- Every state-changing capability has exactly one selected owner: ForgeHX Native > Linux Standard > compatibility backend > Diagnostic.
- Detection alone never authorizes writes; daemon routing validates selected owner for exact device/capability.
- OpenRGB connects to localhost:6742, negotiates protocol 1..=5, and never owns non-lighting capabilities.
- ratbag adapter exposes only backend-reported mouse features and never manufactures unsupported commands.
- ForgeHX manages only ForgeHX-namespaced PipeWire/EQ files under the user config directory.
- Firmware flashing and undocumented writes to unverified devices remain out of scope.
