# ForgeHX v0.2 Universal Devices + NGENUITY-Style UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade ForgeHX to v0.2.0 with universal peripheral discovery, logical-device grouping, daemon-owned support/capability authorization, generic Linux audio controls, and a modular newest-generation NGENUITY-inspired ForgeHX GUI.

**Architecture:** Keep the v0.1 daemon/IPC security boundary. `forgehx-device` becomes a discovery pipeline that collects HID and USB interfaces, classifies and groups them, then attaches verified driver metadata; `forgehx-audio` contributes generic PipeWire nodes; `forgehx-daemon` owns coherent inventory snapshots and permissions. The GUI consumes only daemon-computed logical devices and support levels and cannot issue raw HID writes.

**Tech Stack:** Rust 2021, serde/serde_json, hidapi `linux-native`, tokio Unix-socket IPC, egui/eframe 0.33.3, WirePlumber `wpctl`, Linux sysfs, Arch Linux PKGBUILD/systemd/udev packaging.

## Global Constraints

- Target version is `0.2.0`; Arch `pkgrel=1` for the release source.
- Target Arch Linux / Arch-derived x86-64 Linux, Wayland/X11, PipeWire/WirePlumber.
- Firmware flashing remains disabled.
- Unknown devices may never receive undocumented vendor-specific writes.
- Generic controls are permitted only through explicit Linux-standard backends.
- HyperX Home/Devices excludes unrelated brands; All Devices contains all relevant enumerated peripherals.
- The daemon calculates support level and authorizes every state-changing operation.
- GUI visuals follow the newest NGENUITY design language but use ForgeHX branding and original egui-rendered device artwork.
- Existing v0.1 profiles remain readable.
- No completion/build claim unless `cargo test --workspace` and `cargo build --workspace --release` actually run successfully in the active environment.
