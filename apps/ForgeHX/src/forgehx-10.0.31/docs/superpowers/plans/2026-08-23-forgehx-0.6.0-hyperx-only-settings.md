# ForgeHX 0.6.0 HyperX-Only Inventory and Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ForgeHX 0.6.0 with a HyperX-only GUI inventory and class-specific HyperX hardware settings surfaces without exposing speculative writes.

**Architecture:** Keep daemon-wide discovery for backend correlation, but remove the universal inventory from GUI state and selection. Add a `Hardware` device tab whose controls are derived from existing verified capability owners; audio classes reuse PipeWire controls and non-audio classes expose status/ownership until a writable backend exists.

**Tech Stack:** Rust 2021, eframe/egui, serde IPC, PipeWire/wpctl backend, OpenRGB, libratbag, Python source guards, Arch PKGBUILD.

**Spec:** `docs/superpowers/specs/2026-08-23-forgehx-0.6.0-hyperx-only-settings-design.md`

## Global Constraints

- Canonical release identity is exactly `0.6.0`; Arch `pkgrel=1`.
- GUI inventory and selection use only `hyperx_devices`.
- Daemon `all_devices` may remain internal/backward-compatible but is not consumed by GUI.
- No non-HyperX device becomes selectable or writable through a `DeviceInfo` lookup in the GUI.
- New settings expose only existing verified capability owners.
- Microphone DSP stays input-only; generic/raw firmware flashing remains unavailable.
- No revision/RC/r-number artifact suffixes.
