# AetherAI v0.3.7 — Self-Managing ChatGPT-Style UX + Exact AetherForge Terminal Parity

## Status

**Architecture approved by user on 2026-09-05.**

This document is the canonical design specification for AetherAI v0.3.7.  
Implementation must not reinterpret "match AetherForge Terminal" as "similar", "inspired by", or "same colors."  
**AetherForge Terminal is the visual/schema authority.**

---

## 1. Goal

Turn AetherAI from a developer-operated Rust application into a normal self-managing desktop AI application that behaves like ChatGPT in day-to-day use while remaining local-first and completely free.

A normal user must be able to:

- launch AetherAI from the desktop icon;
- start or continue chats;
- attach files and folders;
- drag/drop files and folders;
- import an official ChatGPT export ZIP into the native AetherAI library;
- install/select/remove local models;
- approve permissions through dialogs;
- see background work and errors in the UI;
- update AetherAI through the UI;
- repair or roll back an unhealthy update through the UI;
- export a diagnostic `.txt` through the UI;
- never need a terminal command for normal use.

At the same time, AetherAI must visually render from the **same canonical AetherForge Terminal schema and rendering primitives**, rather than maintaining a second manually copied theme.

## 3. Hard Product Rules

### 3.1 No-terminal normal use

Normal AetherAI operation must never require the user to:

- run Bash scripts;
- run `cargo`;
- type shell commands;
- manually invoke a verifier;
- manually replace binaries;
- edit configuration files;
- manually move model files into runtime folders;
- use a browser to operate AetherAI;
- use ChatGPT as an embedded or external runtime UI.

The terminal remains optional for developer mode and advanced debugging only.

### 3.2 Completely free

AetherAI v0.3.7 must require:

```text
OPENAI_API_KEY=NO
OPENAI_API_BILLING=NO
PAID_MODEL_REQUIRED=NO
PAID_CHATGPT_REQUIRED_BY_AETHERAI=NO
AETHERAI_SUBSCRIPTION=NO
AETHERAI_CLOUD=NO
PAID_BROWSER_SDK=NO
LOCAL_INFERENCE=YES
```

### 3.3 Native ChatGPT Library only

Imported ChatGPT data is native local AetherAI data.

The runtime must not contain:

- ChatGPT webview;
- embedded ChatGPT website;
- external ChatGPT launch;
- private ChatGPT endpoint scraping;
- cookie/session-token extraction;
- OpenAI API dependence.

Supported ingestion remains the official exported account ZIP already handled by the existing importer.

## 4. AetherForge Terminal Is the Visual Authority

The existing AetherAI `DragonGlassTheme` is **not** the visual authority after v0.3.7.

The authoritative schema is the AetherForge Terminal global theme contract.

AetherAI must consume shared canonical Terminal visual primitives or an extracted shared first-party UI crate generated from that same source. It must not duplicate literal theme constants in a separate AetherAI-only structure unless those values are produced from the shared authority.

### 4.1 Renderer authority

Canonical Terminal renderer:

```text
winit
wgpu
glyphon
cosmic-text
```

AetherAI must migrate away from its raw X11 `XDrawString` / solid-fill renderer for user-facing Linux rendering.

The shared renderer must provide:

```rust
pub trait AetherForgeSurface {
    fn begin_frame(&mut self, viewport: PhysicalSize<u32>) -> Result<Frame, RenderError>;
    fn draw_panel(&mut self, panel: PanelPrimitive);
    fn draw_text(&mut self, text: TextPrimitive);
    fn draw_divider(&mut self, divider: DividerPrimitive);
    fn draw_status(&mut self, status: StatusPrimitive);
    fn draw_control(&mut self, control: WindowControlPrimitive);
    fn end_frame(&mut self, frame: Frame) -> Result<(), RenderError>;
}
```

The exact implementation details may remain inside the shared renderer, but AetherAI must not own a parallel text/render path.

### 4.2 Exact DragonGlass compositing

Canonical values:

```text
global_transparency=0.75
global_surface_opacity=0.25
dragonglass-main-surface-alpha=64
framebuffer-clear=transparent-alpha-zero
titlebar-material=single-pass-25-percent-smoke
dragonglass-frost=smoky-tint-no-opacity-stacking
```

Rules:

- alpha is rendered, not merely stored in a color struct;
- do not use whole-window opacity as a substitute;
- do not stack multiple 25% translucent layers to simulate one panel;
- text/glyph opacity remains independently readable;
- menus, dialogs, tooltips, cards, navigation, composer, Files, Models, Activity, Settings, updater, diagnostics, and permission dialogs all inherit the same material system.

### 4.3 Exact titlebar and controls

Current verified Terminal contract:

```text
window-decoration=aetherforge-dragonglass-native
titlebar-height=28
window-controls=20x20-spacing3
window-controls-side=left
window-controls-order=close-maximize-minimize
window-controls-left-inset=6px
window-controls-palette=bold-electric-blue-indigo-violet
window-controls-glyphs=pale-lavender-white
```

AetherAI must use these values and shared primitives exactly.

Historical Terminal plans that place controls on the right are superseded by the current verified Terminal runtime contract.

### 4.4 Exact typography

Canonical values:

```text
value_text=#F4F1FF
label_text=#A98CFF
heading_text=#B9A5FF
body_weight>=650
heading_weight>=700
primary_font_role=monospace
text_rendering=glyphon/cosmic-text
```

AetherAI must not fall back to X11 core fonts or generic toolkit text for its first-party surfaces.

### 4.5 LCARS/schema parity

AetherAI is not a terminal emulator, so it does not copy terminal-only widgets. It **does** use the same visual grammar:

- shallow LCARS instrument-deck depth;
- priority-accent live headers;
- violet divider lines;
- compact status chips;
- dual-accent focus treatment;
- rounded DragonGlass geometry;
- dense clean sci-fi readouts;
- same spacing scale and text hierarchy;
- same icon/glyph treatment;
- same tooltip/popup material.

Content remains AetherAI-specific.

Examples:

```text
Terminal: active session/status chips
AetherAI: active model/retrieval/activity chips

Terminal: system-info LCARS deck
AetherAI: model/retrieval/context/status deck

Terminal: terminal cell focus frame
AetherAI: chat composer / selected source focus frame
```

### 4.6 Visual drift gate

AetherAI v0.3.7 must contain a machine-readable visual contract shared with Terminal.

At minimum:

```rust
pub struct AetherForgeVisualContract {
    pub schema_id: String,
    pub surface_opacity: f32,
    pub global_transparency: f32,
    pub main_surface_alpha: u8,
    pub titlebar_height_px: u16,
    pub window_control_size_px: u16,
    pub window_control_spacing_px: u16,
    pub window_control_left_inset_px: u16,
    pub value_text: Rgba,
    pub label_text: Rgba,
    pub heading_text: Rgba,
    pub body_weight_min: u16,
    pub heading_weight_min: u16,
}
```

AetherAI tests must fail if this contract differs from the Terminal authority.

No second manually-maintained AetherAI palette is permitted.

### 6.4 Drag/drop

Linux supports X11/XWayland/Wayland-compatible file/folder drop through the new shared window stack.

Windows supports native file drop.

Platform code only translates dropped paths; application attachment state remains owned by AetherAI.

## 7. Self-Managing Runtime

### 7.1 Lifecycle manager

AetherAI gets a first-party lifecycle subsystem:

```rust
pub trait LifecycleManager {
    fn current_release(&self) -> Result<ReleaseInfo, LifecycleError>;
    fn check_for_update(&self) -> Result<UpdateStatus, LifecycleError>;
    fn stage_update(&self, release: &ReleaseInfo) -> Result<StagedRelease, LifecycleError>;
    fn verify_staged(&self, staged: &StagedRelease) -> Result<VerificationReport, LifecycleError>;
    fn activate(&self, staged: &StagedRelease) -> Result<(), LifecycleError>;
    fn rollback(&self) -> Result<(), LifecycleError>;
}
```

Normal user update flow:

```text
update available
→ Download
→ Verify
→ Restart & Update
→ health check
→ success
```

Failure:

```text
new release unhealthy
→ automatic rollback to last-known-good
→ AetherAI starts
→ visible recovery notice
→ Export Diagnostic available
```

### 7.2 Release layout

User-owned atomic releases:

```text
~/.local/lib/aetherforge/aetherai/releases/<version>/aetherai-desktop
~/.local/lib/aetherforge/aetherai/current -> releases/<version>
~/.local/lib/aetherforge/aetherai/previous -> releases/<previous-version>
```

The desktop entry points at the stable `current` launcher path, never a version-specific Downloads worktree.

### 7.3 Update trust

Every update must verify before activation:

- release manifest;
- SHA-256;
- expected version;
- expected architecture;
- package structure;
- executable presence;
- static zero-cost/no-browser contract;
- diagnostic health gate.

Signed manifests should be supported when the AetherForge release pipeline provides signing authority.

### 7.4 No hidden shell requirement

Implementation may internally spawn controlled processes where necessary, but the user does not type commands.

All such actions are:

- bounded;
- logged;
- shown in Activity;
- cancellable where safe;
- represented through UI status.

## 17. Explicit Non-Goals

v0.3.7 does not:

- reproduce ChatGPT's proprietary hosted model/backend;
- require OpenAI API access;
- scrape ChatGPT;
- introduce AetherAI cloud accounts;
- make the terminal mandatory for users;
- delete user source files during attachment/index cleanup;
- silently create durable memory from every arbitrary attachment;
- create a second independent AetherForge theme implementation;
- accept "approximately matching" Terminal visuals as PASS.

## 18. Source Authority / Conflict Resolution

Use sources in this order when visual requirements conflict:

1. **Current AetherForge Terminal verification artifacts** (latest verified runtime contract).
2. **Current AetherForge release manifest/global theme schema authority.**
3. AetherForge Terminal implementation plan/design as structural guidance.
4. Older renders/plans only when they do not conflict with the current verified runtime.

Therefore, an older note that places window controls on the right is superseded by the current verified left-side control contract.

## 19. Spec Self-Review

### Placeholder scan

No TBD/TODO/unspecified implementation obligations remain.

### Internal consistency

- AetherForge Terminal is the only visual authority.
- ChatGPT runtime/browser integration is absent.
- Local inference and zero-cost requirements are preserved.
- Self-management removes normal-user terminal commands without forbidding optional developer mode.
- Update rollback and data migration are separated so binary rollback does not blindly revert user data.

### Scope

v0.3.7 is a single UX-foundation release with three tightly coupled surfaces:

1. shared AetherForge first-party rendering authority;
2. self-managing lifecycle/health;
3. ChatGPT-style native interaction surface (chat/files/models/imports).

The implementation plan should stage these as independently testable tasks inside one canonical v0.3.7 worktree, with visual parity established before broad UI expansion so new surfaces cannot be built on the old renderer.

### Ambiguity resolution

"Match AetherForge Terminal" means **shared schema + renderer primitives + exact verified contract values**, not visual resemblance.

"Behave like ChatGPT" means **normal app UX with chat, attachments, history, native import, and no terminal commands for ordinary use**; it does not mean reproducing OpenAI's proprietary hosted service.
