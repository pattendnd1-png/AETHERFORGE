# AetherAI v0.2.0 Desktop + Live Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the verified AetherAI v0.1.9 Rust foundation into AetherAI v0.2.0: a native DragonGlass desktop app with one unified Chat+Work conversation system, real local model inference, project recovery, project-scoped tools, persistence, and typed Linux/Windows system integration.

**Architecture:** Preserve `aether-core`, `aether-chat`, `aether-model-api`, and `aether-storage` as shared boundaries. Add live model runtime crates (`aether-model-runtime`, `aether-model-gguf`, `aether-model-native`), workspace/tool/system crates, and `apps/aetherai-desktop`; refactor chat generation to streamed provider output through `Arc<dyn ModelProvider>`. `MockProvider` remains test-only, while production startup selects a registered real model or reports that no live model is configured.

**Tech Stack:** Rust 2024; Tokio; SQLite/rusqlite; serde; eframe/egui 0.35.0 with wgpu; mistralrs 0.8.x Rust SDK for the AetherNative path; bundled/managed llama.cpp-family OpenAI-compatible local server for AetherGGUF; reqwest/rustls for local HTTP and model downloads; notify for file watching; sysinfo plus platform-specific adapters for system telemetry; existing self-contained Rust/vendored Cargo workflow.

**Spec:** `docs/superpowers/specs/2026-08-31-aetherai-v0.2.0-desktop-app-design.md`

## Global Constraints

- Version is exactly `0.2.0`; do not overwrite or reissue `0.1.9`.
- `MockProvider` is test-only and normal desktop/CLI runtime must never select `aetherai/mock`.
- Production text generation must be real local inference and stream actual model output.
- AetherAI remains free/local-first; no paid OpenAI or other hosted provider is required.
- Network policy is capability-scoped `Off | Ask | On`, not a global forced-off mode.
- One `Conversation` identity must survive acquisition of workspace, tools, files, project state, and other Work capabilities.
- Linux and Windows are separate canonical platform artifacts.
- AetherForge/Aether Terminal DragonGlass styling is a release acceptance requirement, not optional polish.
- Project/system side effects are permissioned and auditable.
- v0.1.9 SQLite conversations must migrate without loss.
- Every release must generate `AetherAI-v0.2.0-VERIFY.txt` with concise PASS/FAIL endpoints.
- Final Linux source/runtime package remains self-compiling/self-testing with bundled Rust and vendored Rust crates.
- Do not represent unavailable vision/voice/image/computer-control engines as functional in v0.2.0.

### Placeholder scan

The plan intentionally uses `<validated-small-model>` only in an example shell path supplied by the release tester; it is not an implementation placeholder. The production catalog task names a concrete Apache-2.0 Qwen3 0.6B target but requires verification of the exact upstream GGUF filename before committing, because upstream model artifact naming is external and mutable. No runtime code is allowed to depend on an unverified filename.

### Type consistency

- `ConversationSettings.model: Option<String>` is used consistently from Core through storage, CLI, desktop, and runtime selection.
- `ModelBackend::{AetherGguf, AetherNative}` is the only production backend enum.
- `ModelProvider::generate_stream -> GenerationStream` is consumed by both live providers and ChatService.
- `ChatService` uses `Arc<dyn ModelProvider>` so desktop and CLI can share runtime-selected providers.
- Network policy is `NetworkPolicy::{Off, Ask, On}` everywhere.
- Permission policy is represented by `PermissionKind` + `PermissionDecision` and consumed by tools/system UI.
