# OpenDeck v2.0.1 Full Customization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v2.0.0 prototype editor with a compact Windows Stream Deck-style customization workspace that persistently edits all 8 keys, 4 dials, and 4 touch regions, including actions, appearance, states, profiles, pages, folders, assets, drag/drop, and undo/redo.

**Architecture:** React becomes a componentized editor over a typed workspace/reducer model; Rust owns durable workspace/assets/profile persistence through narrow Tauri commands. Existing OBS, Twitch Device Code Flow, and Marketplace handoff remain intact, while editor-native action definitions and persistence are isolated from service transport so future HID/plugin work does not require rewriting the editor model.

**Tech Stack:** React 19, TypeScript, Vite, Vitest/Testing Library, Tauri 2, Rust 2024, serde/serde_json, uuid, sha2, walkdir, existing reqwest/tokio-tungstenite service stack.

**Spec:** `docs/superpowers/specs/2026-09-14-opendeck-v2.0.1-full-customization-design.md`

## Global Constraints

- Canonical version is `2.0.1`; all package/workspace/Tauri version metadata must match.
- Windows Stream Deck workflow/density first; no DragonGlass in this release.
- No background daemon, no autostart, no OBS auto-start, no public-stream qualification test.
- Preserve existing OBS, Twitch Device Code Flow, and Elgato Marketplace behavior.
- Rust is authoritative for durable editor state; localStorage is migration input only.
- At least one profile and one page must always exist.
- 8 keys, 4 dials, and 4 touch regions are independently editable.
- All source-package hygiene, strict Clippy, tests, release build, and Tauri build gates remain mandatory.
- No proprietary Elgato binaries/artwork or retired v1 source are imported.
