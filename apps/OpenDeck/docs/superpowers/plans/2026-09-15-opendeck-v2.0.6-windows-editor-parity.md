# OpenDeck+ v2.0.6 Windows Editor Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the OpenDeck+ editor shell to match the Windows Stream Deck+ editor hierarchy while preserving OpenDeck functionality and applying DragonGlass as the visual skin.

**Architecture:** Keep all existing workspace, action, persistence, Twitch, OBS, and HID semantics. Recompose the React shell into a compact device/profile header, direct device canvas, numbered page strip, selected-control configuration strip, and right-side Keys/Dials action library. The release is frontend-dominant; Rust changes are limited to version metadata only.

**Tech Stack:** React 19, TypeScript 5.9, Vitest + Testing Library, CSS, Tauri 2, Rust 1.98.1 host qualification.

**Spec:** `docs/superpowers/specs/2026-09-15-opendeck-v2.0.6-windows-editor-parity-design.md`

## Global Constraints

- Canonical input baseline is OpenDeck+ 2.0.5.
- Target release is OpenDeck+ 2.0.6.
- Preserve the 2.0.5 Twitch device-auth polling behavior unchanged.
- Preserve HID/runtime, workspace persistence, OBS execution, asset management, profile/page semantics, and udev behavior.
- No Elgato binaries, icons, or protected artwork.
- Windows Stream Deck determines editor geometry; DragonGlass determines visual materials.
- Keep the active 2.0.5 binary until every 2.0.6 host gate passes.
