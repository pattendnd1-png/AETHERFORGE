# OpenDeck+ v2.0.6 Windows Editor Parity Design

## Goal

Rebuild the OpenDeck+ editor shell so its information architecture and control placement follow the Windows Elgato Stream Deck editor for Stream Deck+, while keeping OpenDeck's clean-room implementation, Linux/Tauri runtime, existing workspace semantics, and AetherForge DragonGlass visual treatment.

## Baseline and release boundary

- Canonical input baseline: OpenDeck+ 2.0.5.
- Target release: OpenDeck+ 2.0.6.
- 2.0.5 Twitch device authentication behavior remains unchanged.
- HID/runtime, workspace persistence, OBS execution, asset management, profile/page data models, and udev rules are not redesigned in this release.
- The active 2.0.5 binary must remain untouched until every 2.0.6 qualification gate passes.
- No Elgato binaries, icons, or protected artwork are copied. Layout and interaction are reimplemented from public behavioral references.

## Reference behavior

The Stream Deck+ editor presents a device canvas on the left/center and an action library on the right. The action library has separate Keys and Dials modes, and dial-capable actions are exposed through the Dials mode. Selected controls expose configuration beneath the device canvas rather than in an unrelated generic side panel. Public Elgato documentation also shows device/profile controls in the upper-left and compact app/settings controls toward the upper-right.

Reference pages used for the design:

- Elgato Stream Deck+ — Dials Introduction: https://help.elgato.com/hc/en-us/articles/10715833118989-Elgato-Stream-Deck-Dials-Introduction
- Elgato Stream Deck+ — Dial Stacks: https://help.elgato.com/hc/en-us/articles/10843581380109-Elgato-Stream-Deck-Dial-Stacks
- Stream Deck SDK — Keys: https://docs.elgato.com/streamdeck/sdk/guides/keys/

## Shell hierarchy

The root application becomes a two-row shell: compact editor header plus the editor workspace. The persistent bottom status bar is removed.

The workspace is a two-column grid:

1. `editor-column`: device canvas, compact page strip, then property configuration strip.
2. `action-library`: fixed right-side action browser.

A narrow resize divider remains between the two columns. The property configuration strip may remain vertically resizable, but its visual chrome changes from a generic "Property Inspector" panel to the selected action's configuration surface.

## Header

Replace the current flattened toolbar with two compact groups.

### Upper-left editor identity

- Device selector on the first row, displaying `Stream Deck +`.
- Profile selector directly below the device selector.
- Profile create/rename/duplicate/delete actions move into a compact adjacent menu button rather than four persistent toolbar buttons.
- Hardware connection state is represented by a small status dot/tooltip beside the device selector, not a wide status pill.

### Upper-right application controls

- Undo and redo remain compact icon buttons.
- Connections becomes an icon button with accessible name `Connections`.
- Marketplace becomes an icon button with accessible name `Marketplace`.
- Settings is represented as a compact icon button shell affordance; v2.0.6 may keep it non-modal if no settings surface exists yet, but it must be visually present only if backed by a non-destructive existing action. Do not invent settings behavior solely for parity.

## Device canvas

The Stream Deck+ surface sits directly on the editor canvas. Remove the oversized rounded `deck-plus` outer card treatment.

The device surface keeps the existing editable controls:

- 4 × 2 key grid.
- Four touch-strip regions forming one continuous strip.
- Four rotary dial controls.

Spacing changes:

- Keys use square controls with tighter gaps and no containing card border.
- Touch strip visually reads as one continuous display, with four internal hit regions.
- Dials render beneath the strip with equal horizontal spacing.
- Selection remains visible but must not add layout shift.

The `data-testid="deck-plus"` hook remains for compatibility, but it moves to the direct device-surface wrapper.

## Pages

Replace the current wide select-and-buttons navigator with a compact `Pages:` strip immediately beneath the dials.

- Render one numbered button per page in order.
- Active page is visually selected.
- Add page is a compact `+` button.
- Previous/next selection is represented by choosing numbered page buttons; dedicated previous/next arrows are removed from the persistent strip.
- Rename/duplicate/delete remain available through a compact page menu tied to the active page.
- Existing page operations and data model remain unchanged.

## Action library

The right panel becomes the authoritative action browser.

Header order:

1. Search field.
2. `Keys` and `Dials` mode tabs.
3. Scrollable grouped action categories.

Behavior:

- `Keys` mode shows actions supporting `key` controls.
- `Dials` mode shows actions supporting `dial` or `touch` controls; actions that support neither are omitted rather than shown disabled.
- If a key is selected, the library automatically switches to `Keys`.
- If a dial or touch region is selected, the library automatically switches to `Dials`.
- The user may manually switch tabs when no selection is active.
- Search filters within the active mode.
- Existing drag MIME type `application/x-opendeck-action` and click-to-assign behavior remain unchanged.
- Group headers become collapsible category rows, default expanded.
- Marketplace remains a separate application control in 2.0.6; marketplace search is not merged into the library in this release because the current marketplace model is not an action-catalog provider.

## Configuration strip

Remove the generic visible title `Property Inspector` and its three persistent `Action / Appearance / States` top tabs.

When nothing is selected, the strip displays a quiet instruction: `Select a key, dial, or touch region to configure it.`

When a control is selected:

- Left identity block shows control kind/position and assigned action label.
- Main configuration area presents action configuration first.
- Appearance and state controls remain available through compact secondary buttons inside the configuration strip, preserving all current functionality without making them the primary shell navigation.
- Collapse/expand remains supported.
- Existing `ActionInspector`, `AppearanceInspector`, and `StatesInspector` logic is reused; this release changes composition and chrome, not their data semantics.

## DragonGlass visual layer

Windows Stream Deck determines geometry and hierarchy; DragonGlass determines materials.

- Backgrounds remain very dark and translucent/smoky.
- Borders are minimal and low-contrast.
- Corners are soft but not oversized.
- Indigo/violet accents indicate selection/focus.
- Text and glyphs use pale near-white/light-lavender values.
- Controls remain compact.
- The device canvas itself stays visually quiet so hardware controls dominate.

No large decorative gradients, oversized cards, permanent status bar, or generic dashboard panels are allowed in the editor shell.

## Status and feedback

Remove the permanent `.statusbar` footer. Keep the existing `status` and `saveStatus` state, but expose them through a compact transient status area in the header:

- `saveStatus` is shown as a small save-state indicator near the upper-right controls.
- User-facing action/error status appears as a short-lived toast region anchored inside the shell.
- Errors remain visible long enough to be read and are announced with `role="status"` or `role="alert"` as appropriate.

This is a presentation change only; existing status strings are preserved.

## Component boundaries

- `TopBar.tsx`: compact two-level device/profile identity + app controls.
- `ProfileManager.tsx`: selector plus compact menu, no four always-visible management buttons.
- `DeviceEditor.tsx`: direct device surface without outer card chrome.
- `PageNavigator.tsx`: numbered page strip + active-page menu.
- `ActionLibrary.tsx`: Keys/Dials modes, filtering, collapsible groups.
- `PropertyInspector.tsx`: configuration strip composition and secondary appearance/state affordances.
- `App.tsx`: shell composition, action-library mode ownership, toast/status presentation, removal of footer.
- `styles.css`: all v2.0.6 geometry and DragonGlass shell styling.

No new Rust/Tauri backend surface is required.

## Accessibility and test contracts

Required accessible names:

- Device selector: `Device`.
- Profile selector: `Profile`.
- Connections control: `Connections`.
- Marketplace control: `Marketplace`.
- Action mode tabs: `Keys` and `Dials`.
- Action search: `Search actions`.
- Page buttons: `Page 1`, `Page 2`, etc.
- Add page: `Add page`.
- Page menu: `Page options`.
- Collapse action panel: existing accessible behavior remains.
- Collapse configuration strip: `Collapse configuration`.

Regression tests must prove:

- 8 keys, 4 touch regions, and 4 dials still render.
- Header no longer exposes the old flattened `Stream Deck + · Connected` status pill.
- Device/profile controls remain accessible.
- Selecting a key switches library mode to Keys.
- Selecting a dial or touch region switches library mode to Dials.
- Dials mode excludes key-only actions.
- Page buttons select the correct page and `+` adds a page.
- Configuration strip appears below the device and still edits action/appearance/state data.
- No permanent `statusbar` exists.
- Twitch connection modal and the 2.0.5 polling flow continue to work.
- Existing drag/drop, OBS test-action safety, autosave, hardware event, and workspace persistence tests remain green.

## Qualification gates

The release is not qualified unless all of the following pass on the host:

1. Source/version/interface contract scripts.
2. `npm test`.
3. `npm run lint` with zero warnings.
4. `npm run build`.
5. `cargo fmt --all -- --check`.
6. `cargo check --workspace --all-targets --all-features --locked`.
7. `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`.
8. `cargo test --workspace --all-targets --all-features --locked`.
9. `cargo build --workspace --all-features --release --locked`.
10. Tauri `build --no-bundle`.
11. Stream Deck+ OS probe.
12. Active binary SHA verification after staged activation.

The active 2.0.5 binary remains the rollback target until all gates are green.
